# Project Space — Context

## Domain

Personal project management — from idea through done.
Any goal that requires multiple steps, multiple sessions, or needs to track
progress belongs here.

## Project Model

A project has:
- **Done-state**: a specific, unambiguous description of "done"
- **Milestones**: named checkpoints that represent meaningful progress
- **Tasks**: individual actions that serve milestones
- **Blockers**: obstacles with a named next action

## What Lives Here

- Project definitions, status, and done-states
- Milestone progress and slip tracking
- Active task lists per project
- Blocker log with next actions
- Decision records per project
- Project close documents

## Principles

1. A project without a done-state is not a project.
2. Blockers must have a next action within 24 hours of being logged.
3. Projects with no update in 14 days are flagged as stale.
4. Close every project — outcomes matter for future project planning.

## Boundaries

- Team/work projects → your work tools (Jira, Linear, Notion, etc.)
- Purely financial goals → finance-space
- Learning-driven builds → can span both learn-space and project-space
- Routine recurring tasks → use a habit/routine tool, not this space
